# Audit findings

Baseline `improved` at `221f279`, compared with `main` at `8317430`. These are initial Phase 0 findings. Severity combines likelihood and impact for the observed single-instance deployment and identifies cases whose impact grows with multiple writers.

| ID and status | Severity and evidence | Reproduction or verification | Fix and acceptance |
| --- | --- | --- | --- |
| AUTH-01 · Confirmed at baseline, repaired locally | High. [auth.py](../auth.py:53) uses an in-process lock for the [read and rewrite cycle](../auth.py:65). Independent maintenance or app processes can hold different locks, so operations have no shared serialization guarantee. A fixed temporary pathname also overlaps. | Coordinate independent fixture processes performing distinct account mutations. Check both records survive and that concurrent first registration produces one administrator. Do this on a disposable account file. | Coordinate writers across processes and atomically replace a private file. Preserve JSON format, hashes, workspace IDs and sessions. Add deterministic process-level regression coverage. |
| AUTH-02 · Confirmed policy gap | High on an Internet-facing host. [Account security and bootstrap](../auth.py:94) allow six-character new passwords, open signup, first-account administration and unthrottled bad logins. Duplicate registration distinguishes an existing username. Credential revision already invalidates other sessions on password change. | Inspect signup/login paths and verify these limits using only fixture accounts. Production access controls and exposure are unverified. | Design explicit bootstrap, configurable signup and bounded, observable throttling. Keep existing passwords valid until changed. Exercise response parity, distributed writer behavior and recovery. |
| MAIL-01 · Confirmed at baseline, repaired locally | Medium. The previous broken regex was replaced on `improved`. [normalize_email](../notifications.py:107) strips before validation, silently accepting line breaks at the beginning or end. Unicode/IDN behavior is implicit. | Run the helper against addresses with edge CR/LF, Unicode whitespace and ACE labels. The existing inline newline regression passes. | Reject CR/LF before trimming, document ASCII policy, and test plus addressing, subdomains, maximum lengths and unsupported Unicode. Leave persisted preferences intact. |
| HTML-01 · Confirmed rendering boundary, repaired locally | High. The baseline bill reader interpolated upstream HTML into the component. Status labels and roll-call text also entered HTML-enabled UI blocks. This review established unsafe input handling; no deployed exploit was tested. | Structure-preserving renderer fixtures and targeted review of the affected sinks. | Allow only document structure and escaped text, omit document attributes, and escape dynamic values in trusted formatting. Retain the source link and amendment diff. |
| CI-01 · Confirmed upstream compatibility failure, repair awaiting GitHub | High for release confidence. [The deployed release run](https://github.com/mattcallaway/legiscan_private/actions/runs/45139079392) failed because Playwright 1.58.0 rejected Chromium on the Ubuntu 26.04 runner. Browser and regression steps were skipped. | Verify the pinned OS and separated jobs on the next authorized GitHub run. | Pin Ubuntu 24.04. Run browser and PostgreSQL/unit suites as independent jobs. Both trigger against the working branch. |
| DB-01 · Architectural risk | High with concurrent sessions. The [Streamlit corpus resource](../legiscan_git_sync_update_8_7.py:932) can be reused across sessions and [CorpusManager](../corpus_manager.py:309) opens a shared-thread SQLite connection. Transaction ordering and close semantics need independent validation. | Use concurrent fixture readers and writers through the same cached resource and another process, with lock and crash injection. Source inspection does not establish a production corruption incident. | Introduce explicit connection ownership and bounded transactions while preserving WAL behavior and ingestion semantics. |
| JOB-01 · Architectural risk | Medium. [Worker ownership](../job_manager.py:61) now prevents replacement of a live worker with an expired heartbeat. [CLI and runner](../cli.py) still have multiple direct and queued entry points and depend on common durable paths. | Existing queue recovery and worker lock regressions pass. Add abrupt process exit, ambiguous result, corrupted payload and mixed-version restart fixtures. | Preserve queue IDs and serialized operation scope. Document fencing and supported restart order. Test one writer and stale worker recovery. |
| SCAN-01 · Partial consistency gap | Medium. [Keyword ingestion](../legiscanner.py:208) preserves cached results and merges matches, but old tags and corpus overlay matches persist and source freshness is separate from indexed status. This is documented retention; consumers can still misread old matches as current. | Compare a fixture after adding/removing a term and after partial provider failure across CSV, corpus and the picker. | Distinguish current configuration, historically observed matches and latest scan completeness, without deleting prior evidence. |
| SEARCH-01 · Measured query boundary | Medium. [Corpus search](../corpus_manager.py:1149) uses indexes for several filters and ordering shapes, but literal search computes substring predicates across fields, with a separate count on the normal results page. Warm synthetic samples are in the performance baseline. | Run the harness and capture plans at increasing sizes. Add cross-session query/evidence equivalence before alternate indexes. | Evaluate candidate selection and search indexing with recall and ordering parity. Preserve exact literal and historical behavior. |
| OPS-01 · Confirmed operational dependency | Medium. [Standalone staff job](../sync_staff_directory.py) has a fixed Linux log path and workbook URL. The deployed legacy cron was paused at cutover. PostgreSQL and Resend were unset. | VPS health and admin role were confirmed, but staff schedule, provider delivery and automated authenticated production journeys are unverified. | Test a fixture or preview, reconcile service identity and environment, verify backup, then roll out schedule explicitly. Initialize email only after supplying dedicated production credentials. |
| UX-01 · Confirmed coverage gap | Medium. [Smoke test](../tools/smoke_browser.py) checks health, guest dashboard, coverage, calendar and status labels. Main [Streamlit entry point](../legiscan_git_sync_update_8_7.py) still owns several research/admin flows. | Review browser coverage beside the test matrix. | Add authenticated cross-user, watchlist, search and restore fixtures before extracting high-value slices. |

Other review areas include role boundaries, protected credential storage, filename and content validation, provider failure injection, atomic CSV/SQLite publication, explicit provenance, and multi-step restore. These are open work. The audit reports source evidence and measured fixtures separately from production observations.
